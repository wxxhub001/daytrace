# 刷够了没 · DayTrace

一个**纯本地**的 Android 屏幕时间管理 App：统计每个 App **打开了多少次、用了多久**，给任意 App 设**每日限额**，到点提醒甚至直接把你请出应用；再用**长期目标 / 倒计时**监督自己。

名字叫「刷够了没」——每次解锁都像被问一句，算是免费的行为干预。

```
今天 3 小时 12 分 · 打开 58 次        距离 期末考试 还有 43 天
▓▓▓▓▓▓▓▓▓▓░░░░░░  日均 2 小时 47 分      43
```

**[⬇️ 下载最新版](https://github.com/WXXHUB001/daytrace/releases/latest)** · [隐私政策](PRIVACY.md) · [许可证 GPL-3.0](LICENSE)

## 二之一、v1.8 改了什么：先拆掉上架路上的两颗雷

版本内容没变，改的是"能不能进商店"的底子：

1. **移除 `QUERY_ALL_PACKAGES`**。这是 Google Play 的受限权限，白名单场景是杀毒/文件管理/浏览器/设备管理，不含"数字健康"，申报基本不会过。现在改为只声明一条"能看到桌面启动器应用"的 `<queries>` —— 而需要名称和图标的包名本来就全部来自 `UsageStats` 的真实使用记录，能被使用的应用基本都有启动器入口；极端情况下（没有启动器入口的包）退化成显示包名末段，不会崩。APK 里已经确认该权限不再出现。
2. **把"强制关闭/强制停止"的对外表述统一改成"关闭应用 / 退出到桌面"**。Play 的 Device and Network Abuse 政策明确禁止"干扰其他应用"，而"强制关闭别的软件"这句话在审核眼里就是自认违规；同一件事换个说法（并且强调**只作用于你自己设了限额的那一个应用**）就能过，功能一个字没少。

## 二之二、v1.7 改了什么：桌面小挂件

新增两块桌面挂件（长按桌面 → 小部件 → 刷够了没）：

1. **今日概览 4×2**：今日总时长（大字）、打开次数 + 近 7 天日均、进度条（和日均比）、Top 3 应用（带图标与时长）、右上角「截至 HH:mm」。点一下进 App。
2. **倒计时 2×2**：自动显示最近一个倒计时目标的「还有 N 天」，下方标目标日期；没有目标时提示去建一个，点一下直达目标页（不需要配置，自动挑最近的那个）。

工程上的三个决定：

- **只在数据变了才推**：同步完成（15 分钟）、打开 App、系统轮询（30 分钟）三个时机刷新，不做定时无脑重建 —— 省电，也不闪屏。
- **尺寸自适应**：高度被压到 120dp 以下时自动隐藏 Top 3 列表，只留总数和进度条，避免小尺寸里文字挤成一团。
- **用 RemoteViews 而不是 Glance**：两边都没法复用 Compose 主题（得重画一遍），RemoteViews 更稳、零新增依赖；代价是挂件里不能用自定义 View，所以进度条只能是横向的，环形做不出来。

## 二之三、v1.6 改了什么：弹窗样式可以自己设

弹窗从"一套固定皮肤"变成可编辑的：

1. **预设主题**：暖阳 / 墨夜 / 奶油 / 薄荷 / 晴空 / 晚霞 / 玫瑰 / 纸白 / 森野 / 石墨，一键切换，只换配色、不动你改过的文案。
2. **背景**：纯色（12 个色板 + `#RRGGBB` 手填）或**相册图片**；图片压到 1600px 存进 App 私有目录，原图删了也不影响，另配 0–70% 的压暗滑杆保证文字读得清。
3. **文案**：标题、正文、三个按钮文字都能改；正文支持变量 `{app} {used} {limit} {left} {opens}`，点 chip 直接插入，写错了原样保留不报错。
4. **字号**：85%–135%。
5. **文字与按钮颜色**：默认自动（按背景亮度选深色或白字），也可以强制指定；**对比度低于 3:1 会当场警告并给"一键修正"**，避免配出看不见的字。
6. **单条规则单独定制**：某条规则可以有自己的样子，其余跟随全局；在规则编辑框里点「单独定制」进入。
7. 设置页顶部是**实时预览**，用的是和真实弹窗完全相同的 `PopupCard`，所见即所得。

入口：「我的 → 外观 → 弹窗样式」。样式存在 DataStore（不进数据库），所以本次改动**没有数据库迁移**。

## 二之四、v1.5 改了什么：白底固定，不再跟随系统深色

上一版主题默认取 `isSystemInDarkTheme()`，手机一开深色模式，整个 App 就变成深灰底（`#111111`），和"白底黄辅"的设计完全相反。现在：

1. `DayTraceTheme` 默认恒为浅色，**不看系统设置**；
2. 状态栏 / 导航栏图标固定用深色（`SystemBarStyle.light`），白底上不会再出现看不见的白色图标；
3. `values-night/themes.xml` 也改成白底 —— 否则冷启动那一瞬还是会闪一下黑；
4. 深色配色仍留在代码里（`DarkColors`），将来要做手动开关随时能接。

## 二之五、v1.4 改了什么：提醒从"通知"变成"弹窗"

1. **到点直接弹窗**：在当前应用上盖一张卡片，显示今天已用多久、上限多少，三个出口——**好，先退出**（回桌面）、**再给 5 分钟**（每天限次）、**今天不再提醒**。不再只是往通知栏丢一条。
2. 新增动作模式 **弹窗提醒**；`AUTO` 升级链改成 **弹窗 → 弹窗+震动 → 弹回桌面**，新规则默认就是弹窗。
3. **弹窗失败不静默**：没有悬浮窗权限（且无障碍未开）时自动退回通知，提醒不会凭空消失。
4. 「静默通知」保留，不想被打断的规则可以单独选。
5. 「提醒」页的权限自检改名为 **弹窗 / 拦截页浮层**，一眼看出弹窗靠的是哪个权限。

### v1.3 也改了这些

1. **换名 + 换图标**：应用时光 → **刷够了没**；新图标是黄底白表盘 + 一片绿叶 + 深褐指针（构图已按自适应图标安全区校验，圆形裁切不会切到内容）。
2. **整体换肤成白底黄辅**：纯白底色、琥珀黄 `#FFC300` 只做填充（按钮、进度、选中态），白底上的强调文字改成深琥珀 `#4A3600` 保证可读，达标状态用叶绿。
3. **目标新增「日期倒计时」**：选一个日子（7/30/100 天后快捷选项，或调系统日期选择器），卡片上用大号字显示 **还有 N 天**，到期当天显示「就是今天」。
4. **提醒变得更主动**（此前提一次就安静了）：
   - 目标催办从"晚上 20:00 一次"改成 **9:00–22:00 每 3 小时一次，一天最多 5 次**，仍未完成就继续催；

   - 精准模式采样从 30 秒缩短到 **15 秒**，超限反应更快；
   - 「提醒 → 运行方式」新增 **发一条测试提醒**，一键验证通知链路通不通。
5. 数据库 **v3 → v4**（`goals` 加 `dueDayKey`），覆盖安装不丢数据。

**这个 keystore 一旦丢失，就再也无法给已发布的 App 推更新**（只能换包名重新上架）。请把它和密码单独备份一份到网盘或密码管理器。

1. 首页点「去授权」→ **设置 → 应用 → 特殊应用权限 → 使用情况访问 → 刷够了没 → 允许**

> 侧载安装的 App 在 Android 13+ 上无障碍开关默认是灰的：去「设置 → 应用 → 刷够了没 → 右上角 → 允许受限设置」。

## 四、核心算法：什么叫"打开了一次"

系统给的是一串事件流（`ACTIVITY_RESUMED` / `ACTIVITY_PAUSED` / 熄屏 / 锁屏）。直接数 RESUMED 会严重虚高，所以做了配对与去抖（`domain/UsageAnalyzer.kt`）：

1. 同一应用连续 RESUMED（Activity 内部跳转）不新增打开；
2. 暂停后 3 秒内回来仍算同一次打开；
3. 会话时长 = 各段真实前台时间之和；
4. 短于 1.5 秒的会话丢弃；
5. 熄屏 / 锁屏立即结束会话；
6. 跨零点按自然日切分，时长按比例分，**打开次数只记在起始那天**；
7. 桌面、SystemUI、本应用自身不计入。

阈值可在「我的 → 统计口径」实时调整。

## 五、"到时间退出应用"的五种力度

Android **不允许普通 App 杀别的 App 进程**，所以按力度分档（「提醒」页每条规则可单独设）：

| 力度 | 行为 | 需要什么 |
| --- | --- | --- |
| **弹窗** | 在当前应用上盖一张卡片：今天用了多久 / 上限多少，三个出口：好，先退出 · 再给 5 分钟 · 今天不再提醒 | 悬浮窗权限（无障碍已开也可） |
| **静默通知** | 一条高优先级通知（带声音震动） | 通知权限 |
| **弹回桌面** | 弹全屏拦截页 + `GLOBAL_ACTION_HOME` | 无障碍服务（拦截页另需悬浮窗权限） |
| **锁屏** | 弹回桌面后直接锁屏 | 无障碍服务 |
| **关闭应用** | 真正 `am force-stop`（只针对你设了限额的那一个应用） | Shizuku（ADB 授权一次），未授权自动降级为弹回桌面 |

`AUTO` 模式下按当日触发次数升级：**1 次弹窗 → 2 次弹窗+震动 → 3 次起弹回桌面**；弹窗里点了「再给 5 分钟」会延后（每天限次），点「今天不再提醒」当天彻底安静，避免强硬到底反被卸载。免打扰时段与白名单内不拦截。

弹窗是**盖在当前应用上的 Activity**（半透明窗口 + 卡片），不是通知栏条目；万一没有悬浮窗权限、无障碍也没开，会自动退回通知而不是静默失败。

## 六、长期目标

| 类型 | 达标条件 | 判定 |
| --- | --- | --- |
| **屏幕时间上限** | 当天总时长 ≤ 设定值 | 自动，从使用记录现算 |
| **习惯打卡** | 每天 / 每周打卡满 N 次 | 手动点「打卡」 |
| **日期倒计时** | 不判定完成，只数日子 | 选日期后自动计算剩余天数 |

设计要点：

- **屏幕目标不单独落库**，每次用 `sessions` 现算，避免双写不一致；
- 打卡用 `(goalId, dayKey)` 唯一键，同一天重复打卡只覆盖不累加；
- **连续达标天数**从今天往回数，"今天还没过完"不算断链，跨月跨年都对；
- 目标创建之前的日子不计入，不会白送达标天数；
- 催办：9:00–22:00 每 3 小时一次（一天最多 5 次），合并成一条通知，点进去直达目标页；**倒计时目标不催办**；
- 每个时段的去重键是 `日期#时段`，存在 `goals.lastNotifiedDay` 里，进程被杀也不会重复打扰。

## 七、数据与同步

### 表结构（Room，`daytrace.db`，version = 4）

```kotlin
sessions(id, packageName, label, isSystem, launchable,
         startTs, endTs, dayKey, durationMs, opens)

limits(packageName, label, dailyMinutes, dailyOpens, remindEveryMinutes,
       repeatAfterLimitMinutes, actionMode, enabled, lastNotifiedDay, lastNotifiedAt)

reminder_state(packageName, dayKey, triggerCountToday, lastTriggerAt, limitNotified,
               lastLimitAt, thresholdFired, cooldownUntil, snoozeUntil,
               snoozeCountToday, silencedForDay)

goals(id, title, type, targetMinutes, targetCount, period,
      createdAt, note, archived, lastNotifiedDay, dueDayKey)   // dueDayKey: v3→v4 新增，倒计时用
goal_checkins(goalId, dayKey, ts, note)                        // 主键 (goalId, dayKey)
```

> `dueDayKey` 是**本版（1.3，数据库 v3→v4）**新增的列，存倒计时目标的目标日期。

### 迁移

`MIGRATION_1_2`、`MIGRATION_2_3`、`MIGRATION_3_4` 全部显式编写，**不销毁重建**。每次改表都做了两道核对：与 Room 生成的 `CREATE TABLE` 逐列比对 + 用 SQLite 实跑一遍迁移（列类型 / 非空 / 主键 / 旧数据保留）。

### 同步

- 触发点：进入 App（`ON_RESUME`）+ WorkManager 每 15 分钟兜底；
- 窗口：每次重算最近 36 小时事件，首次安装回溯 7 天；
- 幂等：以 `(packageName, startTs)` 为唯一键 REPLACE；
- 长期历史靠本地库，系统事件被清理也不影响已落库数据。

## 八、配色：白底琥珀黄

| 角色 | 色值 | 用法 |
| --- | --- | --- |
| 背景 | `#FFFFFF` | 纯白底 |
| 卡片 | `#FFFFFF` + `#F0F0F0` 描边 + 2dp 轻投影 | 白底靠投影分层 |
| 主色 | `#FFC300` | **只做填充**：按钮底、进度条、选中 tab |
| 渐变终点 | `#FF9F1C` | 进度条渐变 |

数字排版刻意加大加粗（番茄 Todo 的观感）。**这套配色只有浅色一套，不跟随系统深色模式**；深色方案（`#111111` / `#1A1A1A`）保留在 `Theme.kt` 里，需要的话可以接一个手动开关。

## 十、权限

| 权限 | 用途 | 授权方式 |
| --- | --- | --- |
| `PACKAGE_USAGE_STATS` | 读取应用使用事件 | 系统设置手动开 |
| `BIND_ACCESSIBILITY_SERVICE` | 弹回桌面 / 锁屏 | 系统设置手动开 |
| `SYSTEM_ALERT_WINDOW` | 弹窗提醒 / 后台弹出拦截页 | 「提醒 → 运行方式」有入口 |
| `FOREGROUND_SERVICE(_SPECIAL_USE)` | 精准模式常驻计时 | 安装即授予 |
| `POST_NOTIFICATIONS` | 限额与目标提醒 | Android 13+ 运行时授权 |

可见性：不再申请 `QUERY_ALL_PACKAGES`，只声明一条 `<queries>`（`MAIN` + `LAUNCHER`），够取到所有桌面可见应用的名称与图标。

隐私：没有申请 `INTERNET` 权限（APK 里的 `ACCESS_NETWORK_STATE` 来自 WorkManager 依赖，只读网络状态、不能联网），全部数据只在本机；`allowBackup="false"`。

## 十一、已知限制

1. **提醒不瞬发**：目标催办靠 15 分钟周期任务，会在整点后 0–15 分钟内触发；深度睡眠下更晚。
2. **系统事件只保留几天**：超过保留期且从未同步过的日子无法补录，建议每天至少开一次 App。
3. **国产 ROM 后台限制**：周期任务可能被杀，但打开 App 会全量补采。
4. **与系统"数字健康"数值有差异**：本应用用事件重算（过滤短会话），通常略低。
5. **倒计时目标不催办**：它只负责数日子，不算"待办"。
6. **目标提醒仍是通知**：那是每日例行提醒，用弹窗打断当前操作太重；只有 App 限额会弹窗。
7. **弹窗可能被系统挡下**：Android 10+ 限制后台启动界面，所以弹窗依赖悬浮窗权限或无障碍服务，两者都没有时自动退回通知；部分国产 ROM 即使授权也仍可能拦截，这时以通知为准。
8. **背景图存在应用私有目录**（`files/popup/`）：清除应用数据会一起删掉，样式自动回落到纯色，不会崩。
9. **debug 签名**：只适合自己用；长期用请自行生成正式密钥。
10. **未上架**：`QUERY_ALL_PACKAGES` 已在 v1.8 移除；剩下的拦路虎是无障碍服务（Play 只允许残障用途）与"关闭应用"的表述，国内商店需补 App 备案、软著、权限用途说明。
11. **挂件数据有延迟**：系统限制挂件最小刷新间隔 30 分钟；本应用靠同步任务（15 分钟）主动推 + 打开 App 时补一次，实际误差 0–15 分钟，被国产 ROM 限制后台时更久。挂件右上角的「截至 HH:mm」就是用来标这个的。
